# Лабораторная работа 1. Цветовые модели — вариант 3: RGB ↔ XYZ ↔ Lab

Приложение на Qt 6 / C++ для интерактивного подбора цвета с одновременным
отображением его составляющих в трёх цветовых моделях: **RGB**, **XYZ**
(источник D65) и **Lab** (МКО). Изменение любой компоненты в любой модели
мгновенно пересчитывает две остальные.

## Архитектура (слои Model / View / ViewModel)

| Слой | Каталог | Содержимое | Зависимости |
|------|---------|------------|-------------|
| **Model** | `model/` | Чистая математика перевода цветов: `ColorConverter.h/.cpp`. Ничего не знает про интерфейс: ни Qt, ни GUI, ни ввода-вывода. | только STL |
| **ViewModel** | `viewmodel/` | `ColorViewModel` (QObject): принимает команды от интерфейса, вызывает Model, хранит текущее состояние и признак обрезания, оповещает через сигнал `stateChanged()`. | Qt Core, Model |
| **View** | `view/` | `MainWindow`, `ModelGroupWidget` — только внешний вид: ползунки, точные поля ввода, палитра, превью, предупреждение. Математики в View нет. | Qt Widgets, ViewModel |

Направление зависимостей строгое: `View → ViewModel → Model`. Слои собираются
отдельными целями CMake (`colormath`, `colorviewmodel`, `Lab1ColorModels`),
что физически запрещает обратные зависимости.

## Формулы (по методичке «Формулы преобразования цветовых моделей»)

* sRGB → линейный: `F(x) = ((x/255 + 0.055)/1.055)^2.4` при `x/255 > 0.04045`, иначе `x/12.92`;
* RGB → XYZ: матрица `0.412453 0.357580 0.180423 / 0.212671 0.715160 0.072169 / 0.019334 0.119193 0.950227` (×100);
* XYZ → RGB: матрица `3.2406 −1.5372 −0.4986 / −0.9689 1.8758 0.0415 / 0.0557 −0.2040 1.0570`;
* XYZ → Lab: `L = 116·F(Y/Yw) − 16`, `a = 500·(F(X/Xw) − F(Y/Yw))`, `b = 200·(F(Y/Yw) − F(Z/Zw))`,
  `F(t) = t^(1/3)` при `t > 0.008856`, иначе `7.787·t + 16/116`;
* точка белого D65: `(95.047; 100; 108.883)`.

Обратный переход Lab → XYZ использует симметричную ветку `F⁻¹(f) = f³` при
`f³ > 0.008856`, иначе `(f − 16/116)/7.787` (эквивалентно классическому
`L/903.3` для тёмных цветов).

**Замечание о точности.** Матрица XYZ→RGB в методичке округлена до 4 знаков и
не является точной обратной к прямой (максимум `|M⁻¹M − I| = 2.83·10⁻⁴`).
Поэтому признак выхода за гамут проверяется с допуском `5·10⁻⁴` в линейной
шкале: это отделяает шум округления от реального выхода за гамут (невидимого
на экране: ≤ 0.03/255) и фиксирует настоящее обрезание.

## Возможности интерфейса

* **Три способа задания цвета в каждой модели:**
  1. точный ввод целым числом (`QSpinBox`; компоненты отображаются
     округлёнными до целых, внутренние значения хранятся с полной точностью);
  2. плавное изменение ползунком (`QSlider`);
  3. выбор из палитры (`QColorDialog` — как в графических редакторах);
* автоматический пересчёт всех моделей при изменении любой компоненты;
* крупное превью цвета с HEX-кодом;
* кнопка **«i»** рядом с палитрой — встроенная справка с гайдом по использованию
  программы;
* **ненавязчивое предупреждение** при «некорректных цветах»: внизу под ползунками
  закреплена жёлтая панель постоянного размера (макет не «дёргается»); если
  введённый XYZ/Lab-цвет не существует в sRGB, в панели появляется текст вида
  «Цвет вне диапазона sRGB: выполнено обрезание компонент (R, B)», а RGB-поля
  показывают обрезанные значения; при возврате в гамут текст исчезает.

## Сборка

Комплект: Qt 6.11.0 (MinGW 64-bit), CMake, Ninja.

**Qt Creator:** открыть `CMakeLists.txt` (Файл → Открыть файл или проект…),
выбрать комплект Desktop Qt 6.11.0 MinGW 64-bit, собрать и запустить.
Создавать новый проект не нужно — проект уже настроен под CMake
(CMakeLists.txt в корне); qmake (.pro) не используется.

**Командная строка (PowerShell):**

```powershell
$env:Path = "E:\Qt\Tools\CMake_64\bin;E:\Qt\Tools\Ninja;E:\Qt\Tools\mingw1310_64\bin;E:\Qt\6.11.0\mingw_64\bin;" + $env:Path
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=E:/Qt/6.11.0/mingw_64 -S . -B build
cmake --build build
build\Lab1ColorModels.exe                    # приложение
```

## Готовая сборка (exe)

Исполняемый файл передаётся отдельным архивом `Lab1ColorModels-exe.zip`
(`Lab1ColorModels.exe` + все нужные DLL — запускается на любом Windows 10/11
x64 без установки Qt) и в репозиторий не входит. Пересобрать самостоятельно:

```powershell
Copy-Item build\Lab1ColorModels.exe deploy\
windeployqt --release --compiler-runtime --no-translations deploy\Lab1ColorModels.exe
```

## О цветовом графике МКО (кратко к теории)

Цветовой график МКО 1931 г. (x, y) — проекция цветового пространства на
плоскость хроматик: `x = X/(X+Y+Z)`, `y = Y/(X+Y+Z)`. Область всех видимых
цветов ограничена кривой спектральных цветов и линией пурпурных. Треугольник
sRGB, вершинами которого служат хроматики основных цветов монитора (R, G, B) и
точка белого D65, лежит внутри этой области, поэтому часть физически возможных
цветов XYZ (например, XYZ(0; 100; 0) — чистая «зелёная» спектральная энергия)
не выражается в sRGB — именно такие случаи приложение показывает как
«выход за гамут» с обрезанием.
